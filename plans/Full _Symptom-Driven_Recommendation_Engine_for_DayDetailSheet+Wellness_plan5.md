## 3. Changes

### 3.1 `symptomSafety.ts` — symptom-triggered red flags (Rule 3B→3A)

Add a **symptom→severity threshold** map (frozen, matches the user's table):

```ts
export const RED_FLAG_RULES: Record<string, number> = {
  'Heavy / Prolonged Bleeding': 5,   // severity >= 5 (or intense)
  'Severe Abdominal Pain': 5,        // pain >= 5 (alias: menstrual cramps at 7+)
  'Absent Period / Amenorrhea': 3,   // severity >= 3 (any logged)
  'Irregular Cycles': 5,             // severity >= 5
  'Vomiting': 5,                     // severity >= 5 (or frequent)
  'Fainting / Dizziness': 5,         // severity >= 5 (see alias note below)
  'Vision Changes': 5,               // resolves to master row vision-changes (PR 1, Note 2)
  'Severe Depression / Self-Harm': 3,// resolves to master row severe-depression (PR 1, Note 2)
  'Chest / Breast Pain': 5,          // severity >= 5
  'Unusual Discharge': 5,            // severity >= 5
  'Frequent UTI Symptoms': 5,        // severity >= 5
};
```

**Integration:** `getSafetyTier(input)` is called by `DayDetailSheet` with
`{painLevel, selectedSymptoms, severities}`. Extend its signature so tiers become:

- `seek_care` if (pain >= `SEEK_CARE_THRESHOLD`) **OR** any `RED_FLAG_RULES[name]` satis­fied
  (severity compare via `severities[name] ?? 1`), **OR** `severities[name]` itself >= 7.
- `recommendation` → engine (PR 3) returns cards.
- `maintenance` → engine motivation (PR 3).
- `motivation` → unchanged (default when nothing matches).

**Alias/name mapping (Note 2 — resolved):** the user's table lists "Fainting/Dizziness",
"Vision Changes", "Severe Depression", "Chest/Breast Pain", "Unusual Discharge", "Frequent
UTI". `vision-changes` (general) and `severe-depression` (mood) are **added to PR 1's
master**. The remaining red-flag names resolve to existing/new master rows:
`Dizziness`, `Unwell`, `Palpitations`, `Painful Urination`, `Breast Tenderness`,
`Heavy / Prolonged Bleeding`, `Absent Period / Amenorrhea`, `Vomiting`. Where the user's
phrase is not an exact master name, map it in the table comment (e.g. "Frequent UTI
Symptoms" → `Frequent Urination / UTIs`); if unknown, tier falls back to defaults (no throw).

### 3.2 Wellness surface — `DynamicRecommendations.tsx`

- Split the file: keep existing hardcoded wellness list, **prepend** a "For today"
  block generated by `getRecommendations(getRecommendationInputFromDay(dayData))` when

  `dayData.cyclePhaseKey ?? 'follicular'`; `painLevel` from `dayData.pain ?? 0`;

  pr-4 action is deep-linked; `'mark-done'` persists via the existing
  `wellness.recs.done.${id}` key.
