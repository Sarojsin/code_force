Two sections stacked:

1. Period-arrival prompt (via usePeriodCheckIn)

Reads calData.needs_checkin + the AI prediction from the already-fetched cycle calendar.
If needs_checkin is true, shows the StickyCard: "We expected your period around {date}. Did it arrive?"
Yes, on {date} → useLogCorrection mutation creates a period entry (with corrected_prediction_id), then clears snooze state → card hides.
No, adjust date → bottom sheet with date picker → logs correction → hides.
Not yet → useLogSnooze mutation + saves a snooze to AsyncStorage (shecare.sticky_snooze) with day offset; card stays hidden for that window.
2. Daily mood check-in

useMoodLogs() fetches your last 30 days; finds if today (logged_at starts with today's date) already has a mood.
Not logged → shows "How are you feeling today?" with a horizontal quick emoji row (8 moods). Tapping one fires useCreateMoodLog({ mood, intensity: 5 }) inline — no navigation. "More options + add a note →" navigates to the full MoodLog screen.
Already logged → shows the mood bubble + "logged today" + an Update button → MoodLog.
CatchUpCard (src/components/home/CatchUpCard.tsx)
Backed by useCatchUp. Returns null (invisible) when there's nothing pending. Otherwise:

1. Unconfirmed end date → EndDatePromptCard

Fires when useEndDateStore has a pending entry (a logged period with no end date yet).
Shows "Your period started N days ago on {date}. Has it ended?"
Yes, it ended → useUpdateCycleEntry sets period_end_date = today, cancels the scheduled end-date notification, clears the pending state → card disappears.
Skip → cancels notification + clears pending.
2. Missed periods → BackfillCards

getBackfillCards(entries, today) from the last logged period entry: if it's been ≥ 56 days since the last period start, it generates up to 3 backfill cards for the missed months (28-day cadence, reverse-chronological, most recent first). No cards for anovulatory last entry.
Each card: "Did you have a period in {Month}?"
Log period → inline date field → useCreateCycleEntry (cycle_type menstrual) → card marked done.
Skip — No period → useCreateCycleEntry (cycle_type anovulatory) → card marked skipped.
Cards are chained: card 2 is disabled until card 1 is done/skipped. Done/skipped state is local (useState in the hook) so it resets when the app restarts, but the underlying entries persist server-side.
