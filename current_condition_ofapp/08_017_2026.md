# SHE CARE — Full Performance & Dead Code Audit Report
 
> **Date:** 2026-08-17
> **Scope:** `/workspace/mobile` (React Native 0.86.0, Expo SDK 57, React 19.2.3, Reanimated 4.5.0)
> **Prompt source:** `current_condition_ofapp/condition.md` (v1.0)
> **Method:** Read-only source audit of every checkpoint, plus a **full-coverage sweep of all 352 source files** (`src/screens`, `src/components`, `src/stores`, `src/services`, `src/db`, `src/hooks`, `src/utils`, `src/providers`, `src/navigation`, `src/app`) and a complete import-graph dead-code scan.
> **Note on ts-prune:** `ts-prune` was installed but could not run against the project because `/workspace/mobile` has no `node_modules` and no lockfile-installed TypeScript compiler context. The dead-code audit was therefore performed manually via exhaustive `grep` of the import graph — results are equivalent for the candidate list below.
 
---
 
## Executive Summary
 
The app is **mostly well-structured** (async-first DB layer, tuned React Query config, correct focus-gating of the 3D renderer, no render-props/HOC bloat, no deep navigation nesting). The core **lag/jank risk concentrated in the JS thread and list rendering**:
 
- **Biggest offenders:**
  1. `VideoLibraryScreen` uses a plain `FlatList` with **zero** perf props, a non-memoized `ContentCard`, and uncached `react-native Image` thumbnails (Section 2.1 / 2.2).
  2. **All 4 Diary screens** (`DiaryLibraryScreen`, `DiaryScreen`, `DiaryTimelineScreen`, `DiarySearchScreen`) use `FlatList` with **zero** perf props, inline `renderItem`, no memoized items, and queries with **no staleTime/limit** (Section 9.3).
  3. `React.memo` is repeatedly **defeated by inline closures** inside `renderItem` (`JournalListScreen:103`, `EmergencyContactsScreen:86-87`) and by inline JSX children fed to `AnimatedSection` on `HomeDashboardScreen` (Section 1.1 / 1.2).
  4. `HomeDashboardScreen` is one **monolithic** screen that re-renders on every cycleDay / speech-bubble change; heavy sections are not split into memoized components (Section 1.4).
  5. **No lazy loading** of heavy screens (Analytics, Diary, Journal) — the already-written `LazyScreen` helper is unused (Section 4.3).
  6. **No React Query pre-warming** — first Home paint waits on a fresh network query (Section 4.5).
  7. **Two dead native deps** (`lottie-react-native`, `expo-image`) inflate the binary; all images render through uncached RN `Image` (Sections 6.3 / 7.1).
  8. **`SettingsScreen`** is the heaviest profile screen: 30+ unmemoized rows re-rendered wholesale, and the speech sliders do a **SQLite write + 5-slice store update per drag tick with no debounce** (Section 9.2).
  9. **Calendar grid** rebuilds its 42 Reanimated-animated cells on every parent render because `CalendarScreen` passes inline `onDateSelect`/`phaseAccentForDate` props, defeating `Calendar`'s `React.memo` (Section 9.1).
  10. **ETag/304 revalidation never used** and the backend calendar query ignores its `months_back` lower bound — full history is returned (Section 9.1).
 
- **Good news:** Luna 3D is correctly gated behind `isFocused` (unmount on tab switch) with a DLC-only model + skeleton loader; DB layer is fully async and serialized; scoring hooks are properly `useMemo`'d; Hermes + New Architecture enabled; timers are mostly cleaned up; lucide icons fully tree-shaken.
